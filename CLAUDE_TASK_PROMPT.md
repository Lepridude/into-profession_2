# Промпт для Claude Code — завершение практической работы № 2

Репозиторий: https://github.com/Lepridude/into-profession_2

Твоя задача — максимально самостоятельно завершить практическую работу № 2 «Работа с LLM через API» по методичке, которая находится в проекте или репозитории. Цель — получить полностью готовую работу, чтобы студенту осталось выполнить минимум действий вручную.

## 1. Изучи проект и методичку

- Прочитай методичку целиком, включая последние страницы с требованиями к сдаче.
- Проверь все ветки: `master`, `env-feature`, `llm-improve-1`, `llm-improve-2`.
- Изучи существующие ноутбуки, CSV-файлы, README и рефлексию.
- Сопоставь реализацию с каждым требованием методички.
- Не переписывай работающие части без необходимости.

## 2. Критически важное ограничение: секреты

**НЕ ТРОГАЙ API-КЛЮЧ И ФАЙЛЫ КОНФИГУРАЦИИ СЕКРЕТОВ.**

- Не открывай, не выводи, не копируй и не изменяй `.env`, `.env.example`, Secrets и другие файлы с ключами.
- Не добавляй ключ в код, Git, логи или коммиты.
- Не меняй существующую конфигурацию подключения к GigaChat.
- Если для проверки API нужен ключ, используй уже настроенный способ его получения, не раскрывая значение.
- Если без действия студента запустить API невозможно, подготовь всё остальное и оставь только этот шаг.

## 3. Доведи ноутбуки до рабочего состояния

Проверь и при необходимости исправь:

- импорты и зависимости;
- чтение исходного CSV;
- обработку всех 15 заявок варианта 01;
- обычный промпт и Few-shot;
- извлечение структурированных полей во второй части;
- Pydantic и JSON-парсер;
- сравнение с ручной разметкой;
- расчёт accuracy и обработку ошибок;
- сохранение результатов в CSV и JSON.

Убедись, что ноутбуки можно последовательно запускать сверху вниз. Исправляй ошибки, но не подставляй выдуманные результаты модели.

## 4. Проверь соответствие методичке

Особенно проверь:

- правильность разделения работы между ветками;
- наличие нужных файлов в нужных ветках;
- использование GigaChat-2 с параметрами из задания;
- оценку первой части по столбцу `amount`;
- оценку полей второй части по ручной разметке;
- наличие рефлексии на 10–12 предложений, если это требует методичка;
- корректность названий файлов и оформления.

Не объединяй `llm-improve-2` с `master`, если методичка требует оставить вторую часть в отдельной ветке.

## 5. Проверь данные и метрики

1. Составь таблицу соответствия: требование методички → где реализовано → результат проверки.
2. Убедись, что вариант 01 соответствует номеру студента в списке и используются именно 15 нужных заявок.
3. Проверь ручную разметку `gold_fields_01.csv`: не угадывай значения, которых нет в заявке. Неоднозначные значения обрабатывай согласно методичке.
4. Проверь, что пропущенные и некорректные ответы не засчитываются как правильные.
5. Проверь обработку диапазонов дат, количества ночей и стоимости согласно правилам задания.
6. Убедись, что результаты запуска сохраняются и могут быть воспроизведены.
7. Не выдумывай метрики, ответы API и примеры ошибок модели. Не выдавай тестовые или демонстрационные ответы за реальные результаты GigaChat.
8. Если реальный запуск API недоступен, явно укажи это и подготовь проект к запуску.

## 6. Git и безопасность

- Если доступ к GitHub есть, внеси необходимые изменения непосредственно в репозиторий.
- Работай в правильных ветках и делай небольшие осмысленные коммиты.
- Не перезаписывай историю и не удаляй чужие изменения.
- Не трогай файлы с ключами и конфигурацией секретов.
- Проверь историю на случайное попадание секретов, не раскрывая и не копируя найденные значения. Если обнаружен опубликованный секрет, сообщи об этом отдельно; не пытайся самостоятельно его использовать.
- Удаляй временные файлы и дубли только если точно установлено, что они не нужны.

## 7. Документация и качество

- Добавь понятные Markdown-комментарии в ноутбуки.
- Добавь краткие инструкции по установке и запуску.
- Проверь, что в репозитории нет фиктивных результатов, заглушек и незаполненных обязательных частей.
- Проведи повторную проверку после всех изменений.
- Оцени, что может снизить оценку преподавателя.

## 8. Финальный отчёт

В конце предоставь:

1. Что требовала методичка.
2. Что было исправлено.
3. Какие файлы и в каких ветках находятся.
4. Какие проверки действительно выполнены и с каким результатом.
5. Что осталось сделать студенту вручную.
6. Какие команды или ячейки нужно запустить для получения настоящих результатов GigaChat.
7. Ссылки на итоговые ветки и коммиты.
8. Таблицу соответствия всем требованиям методички.

**Главное:** не ограничивайся рекомендациями и списком проблем. Самостоятельно выполни всё, что технически возможно. Если действие невозможно без участия студента, не имитируй его выполнение — подготовь всё до этого этапа и чётко укажи единственное необходимое действие с его стороны.
